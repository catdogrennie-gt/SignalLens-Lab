# 推理模式与输出预算：单样本对照

同一份冻结历史锁证据的三次真实调用均未达到完整语义验收。**停止这一方向，转向更简单案例的准备。** 这不是新的故障复现，也不算自主发现成功；生产仍使用关闭 thinking、输出上限 4000 的配置。

三次均使用相同模型、提示和证据消息，没有加入故障开关动作、恢复方式或预期答案。第一次是受控的历史重新分析；后两次是独立离线对照，各调用一次，无自动重试、工具执行或平台报告入库。

| 模式 | 输出上限 | 实际输入 + 输出 = 合计 token | 其中推理 token | 最终输出与校验 | 语义结果 |
| --- | ---: | --- | ---: | --- | --- |
| thinking 关闭 | 4000 | 5711 + 1569 = 7280 | 未单列 | JSON 完整 | 失败：无依据认定自行恢复，混用数值与快照的计数、引用 |
| thinking 开启，low | 4000 | 5711 + 4000 = 9711 | 4000 | `length`；最终内容为空，无 JSON 可校验 | 无法语义比较；输出失败 |
| thinking 开启，low | 8192 | 5711 + 5105 = 10816 | 3454 | `stop`；最终 JSON 5080 字节，生产 v4.4 schema 与 exact-ID 引用校验通过 | 失败：仍认定自行恢复，从 min/max 推断其余样本全为零 |

第一次到第二次只改变 `thinking.type` 和 `reasoning_effort`。第二次到第三次请求体只改变 `max_tokens: 4000 → 8192`，属于明确的**离线输出预算分配实验**，没有修改生产配置。推理与最终答案共用输出额度，推理 token 已包含在实际输出 token 中，不能重复相加。

按既有预算计算口径，后两次请求体均为 23149 字节，另加 512 预留，输入上界为 23661，小于 24000；8192 输出预留对应总上界 `23661 + 8192 = 31853 ≤ 32000`。这是提交前的预算上界，和表中的提供方实际 token 用量分开记录，不代表 8192 在所有输入下都能放入预算，也不构成生产提额。

## 结论边界

8192 实验正确区分了 **720 个数值样本**与 **5 个保留锁快照**，正确引用两次非空快照，并保持等待方请求锁属性与阻塞方身份的归属。但后续空快照不能证明“自行恢复”或精确持续时长；`sample_count=720、min=0、max=1` 也不能证明非零样本的个数或“其余全为零”。格式和引用 ID 合法，不等于结论受证据支持。

每个配置仅有一次调用，且来自同一份历史输入，没有统计意义，不能宣称 thinking 提高了准确率。推理正文保留在私有审计中，不公开，也不作为事实证据。原始冻结证据、原报告及失败响应均保留；这两次离线实验没有创建生产任务或报告，也没有执行新故障。费用未取得可核验结算，不作推算。

不再追加模型调用或扩大输出预算。下一步先准备证据更简单、问题更明确的单一案例，分别核对事实、解释和恢复边界；尚未复现或验收的内容不计为通过。机器记录见 [reasoning-mode-budget-comparison.json](reasoning-mode-budget-comparison.json)。
