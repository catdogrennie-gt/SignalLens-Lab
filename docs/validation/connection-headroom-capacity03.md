# 连接容量风险：CAPACITY-03 实测

**已发现容量水位超限并验证恢复；AI 最终报告因预算不足未生成，本轮整体未通过。** 目标仅是判断当前连接用量、容量、占比和剩余位置，不要求证明宕机、连接泄漏或具体 SQL 根因。

## 实测结果

2026-11-12，以下时间均为 UTC：

| 阶段 | 实测 |
| --- | --- |
| 开关前 | 8/40，占用 20%，剩余 32 |
| 开关打开后 | 33/40，占用 82.5%，剩余 7，超过明确配置的 80% 关注水位 |
| ON / OFF | 19:55:26.211134 / 19:56:05.740205，控制请求接受间隔 39.529 秒 |
| 自主分析窗口 | 截止时间为 ON 后 22.904658 秒，满足原有至少 20 秒门槛 |
| 恢复 | 19:56:28.513205、19:56:43.510870 两次不同的新鲜同步观测均为 8/40 |

固定发生器最多增加 25 个只读连接，没有修改 MySQL 的 40 个连接上限。此次只打开一次，配置了 180 秒控制租约和 170 秒独立关闭保护，实际提前关闭；到期保护随后确认已无本次活动故障。控制接受间隔不等于精确持有连接时长，恢复也不代表数据库整体健康。

## 数据与分析链路

复用 Zabbix 的五个已选监控项：连通性、官方当前连接数、运行线程数，以及带显式容量标签的连接用量和连接上限。关键两项使用 `gauge` 语义、5 秒同步采样；平台按三个时间配对的实际样本计算风险。这里的 80% 是显式配置水位，不是 MySQL 硬上限或官方模板默认告警。

B 自主检查并创建了新任务，没有手工提交采集或 AI 分析。冻结范围与当时选定的五项一致，共 **947 条清单记录：941 条原始观测、5 个数值时间窗、1 条覆盖说明**，没有混入其他聚合指标。该范围和 20 秒窗口合同通过独立只读核对。

真实模型执行了两次请求，两次都返回读取证据的工具调用，没有最终报告正文：

| 请求 | 输入 token | 输出 token | 合计 |
| --- | ---: | ---: | ---: |
| 第一次 | 5096 | 136 | 5232 |
| 第二次 | 5771 | 110 | 5881 |
| 合计 | 10867 | 246 | 11113 |

平台随后以 `model_token_budget_exhausted` 安全终止，没有发出第三次模型请求、增加预算或把工具响应当成有效诊断。实际用量不等于剩余输入可以任意增长；后续请求仍须同时满足输入、输出预留和累计预算约束。原任务保持失败，没有改写为成功。

### 后续预算修复的验证范围

真实输入的离线复核定位到：最终轮剩余输入额度为 16887，空数值表仍携带无用解码元数据，使压缩结果为 17074，超过 187。只清理空表列与空字典后，结果降至 **16683**，本轮累计预算预留为 **31796 ≤ 32000**；触发引用、两项信号和实际容量配对事实不变，没有提高任何预算上限。定向回归先复现再通过，完整平台测试为 **1099 通过、10 跳过**。

这是纯离线输入回放，不是第三次供应商调用或新成功报告。随后 [CAPACITY-04](connection-headroom-capacity04.md) 确实生成了最终报告，但仅一次调用直接输出，没有实际再次经过原“两次工具调用后的最终轮”分支；不能用它宣称该失效路径已完成真实回归。其容量风险解释仍未通过独立语义审查。

## 前提检查与验证程序的边界

开始前先检查所需数据是否已接入、能否配对以及是否新鲜。最初两次平台观测超过 20 秒新鲜度门槛，因此没有立即打开故障；后续自然采样恢复到约 5 秒，且上游与平台时间一致。两个容量项是同一主监控项的 JSONPath 提取，没有丢弃未变化值或心跳预处理。

预演还发现 A 原有加速并不包含 AI 周期，首份报告若过早冻结，后续可能要等 3600 秒。因此复用已有 45 秒可续租机制，在本轮临时采用 30 秒分析间隔；没有修改配置文件或长期策略，关闭后实际读回 3600 秒。低运行线程数不作为否定容量风险的依据。

私有验证程序另有一个检查路径错误，异常后立即关闭了故障；其原始失败状态保留。事后只读核对确认真实任务的范围和 ON 后 22.904658 秒冻结窗口有效。这是验证程序错误，与模型最终预算不足分别记录，既不丢弃真实测量，也不将本轮整体标为通过。

此前 [v4.2 验证](connection-headroom-v42.md) 的 18.06 秒报告窗口仍未满足原 20 秒合同，没有回改旧门槛或旧结果。本轮没有复核 Zabbix 告警事件，不声称 Zabbix 无法告警。故障入口仍仅供内部验证。机器记录见 [connection-headroom-capacity03.json](connection-headroom-capacity03.json)。
