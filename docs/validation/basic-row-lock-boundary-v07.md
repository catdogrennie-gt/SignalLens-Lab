# LOCK-02：在所选证据范围内验证基础锁等待

**本轮通过了即时锁等待诊断、等待方与阻塞方关系、请求侧锁属性、输入范围限制及关闭后的恢复验证。后续恢复报告仍有样本范围表述不准确的问题，因此不标记为全部语义通过。** 公网故障开关保持关闭，只可查看完整分析平台。

本例延续 [LOCK-01](basic-row-lock-v43.md) 的同一基础锁等待场景，机器记录见 [basic-row-lock-boundary-v07.json](basic-row-lock-boundary-v07.json)。它不要求证明 Zabbix 无法告警，也不尝试推断具体 SQL、持锁时长、连接健康或完整根因。

## 先检查证据，再开启一次故障

此次只选择 **完整的当前锁等待快照、锁等待数量** 两项。使用已有 Zabbix 只读来源、现有隔离 MySQL 及唯一固定故障控制器，没有新增 SQL 形状或扩大负载。

开启前依次确认：采集契约为 `db-evidence-lock-snapshot-v2`，当前快照完整；已有两次新鲜空快照；旧锁问题已恢复；没有同对象待处理分析任务；巡检权限、外发许可和当日预算可用。Zabbix 项配置每 5 秒采样，平台配置每 10 秒采集、每 5 秒检查，实测时间以真实样本为准。

前次预演发现过“移出选择的旧线程指标仍可能进入新分析”的缺口。07 版本在自动派发时捕获服务端所选来源、监控项及版本，消费任务和冻结时再次验证。只读预演确认旧自动任务缺少范围会被拒绝，旧线程证据从新的候选清单中排除；兼容的所选历史仍保留，既有冻结报告不改写。然后才执行本轮唯一一次受控演练。

## 首份诊断说对了什么

报告 `04ed3da0-e940-4025-9b9b-8ca7f1863c92` 由平台自主发现后生成，使用一次真实 DeepSeek 调用。实际模型输入和原始快照一致：**等待事务 3854 被事务 3852 阻塞；`RECORD` / `X,REC_NOT_GAP` 属于等待方请求的锁属性**，没有冒充阻塞方持锁模式。

结论明确观察到了记录锁等待，具体 SQL、持续时间和完整根因保持未知。建议人工只读核对会话与语句映射、锁对象，并继续观察后续快照；没有执行杀会话、提交事务或其他修复操作，也没有再从运行线程数推断连接健康。

新冻结清单只包含所选两项的证据和一条对应的数值窗口：576 条证据记录、720 个数值点，移出的线程项和聚合指标帧均为 0。证据记录包括同次采样的通用文本及结构化投影，**不等于 576 次独立上游采样**；原始载荷哈希及清单引用逐项匹配。没有向模型提供场景答案，也没有放宽调用预算或权限。

## 恢复后能看到什么

只读访客访问首份报告及它自己的冻结曲线均返回 HTTP 200，曲线包含 720 个点。使用同一封存版本的只读内部投影核对，这份报告可形成 12 个节点、9 条边；这项图统计是内部投影核验，不是修改公开接口来强制选择旧报告。

随后平台自主生成了更新的恢复评估 `7e90b967-9ac3-42d5-8095-079848b257ca`，其中实际保留了本轮后一个非空快照及之后的空样本。当前问题页采用这份更新，页面访问成功，包含 720 个点及 12 个节点、11 条边。**默认报告更新本身不能判定为缺陷**，因为它补充了真实恢复情况；首份报告仍可单独查看。完整平台入口见 [DB Evidence Platform](https://github.com/catdogrennie-gt/db-evidence-platform)。

## 新发现的缺口：保留样本不等于整个窗口

恢复报告的完整冻结清单实际上有两个非空快照，分别为 18:03:17 和 18:03:42，阻塞方相同。为适应输入预算，最终给模型的锁快照保留了后一个非空样本和前后空样本。

报告却将“所给保留样本中只有一个非空快照”扩大成“整个窗口只出现一次”。这超出了输入所能证明的范围，是接下来的 **SAMPLE-SCOPE-01**：需要明确每个数量究竟来自完整冻结窗口，还是仅来自模型当前收到的投影。保留输入、冻结证据和原报告，不能通过改写历史报告掩盖这一问题；后续可直接用这些实际材料验证，无需再次制造故障。

另外，两份报告都提到四个保留空样本，但对应引用数组只列三条，输入也明确标注还有一个引用被省略。这是尚待完善的引用覆盖问题；不能把“四个保留样本为空”解释成整个时间段持续无锁等待。

本轮结论因此分开记录：**基础即时锁关系诊断通过、输入边界通过、恢复通过；后续报告的全窗数量表述与引用完整性尚未全部通过。** 没有核查本轮 Zabbix 告警事件，不声称本例是 Zabbix 未告警的问题。

## 后续改进与历史重分析

针对上面的样本范围缺口，v4.4 改为保护同一监控项最早与最新的非空快照，保留来源身份，并说明保留快照数量不能当作故障次数或整个窗口的完整统计。本轮实际输入也保留了前后的空样本；预算不足时仍须拒绝超限请求，不能承诺所有窗口都能保留全部样本。

随后只对同一历史窗口进行了**一次手工受控重分析**，没有再次开启故障，也没有把它算成新的自主发现。新冻结清单与原清单的 579 条原始引用完全相同；模型确实收到了两份非空快照，并不再声称整个窗口只有一次。但输出仍有“自行恢复”及数值样本与快照样本引用混用的问题，**不标记为完整语义通过**。旧报告保持原样，完整对照见 [SAMPLE-SCOPE-01 · v4.4 验证](basic-row-lock-sample-scope-v44.md)。
