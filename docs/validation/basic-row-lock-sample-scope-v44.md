# SAMPLE-SCOPE-01：保留两份真实快照，再检查 AI 是否说对

**输入保留与来源边界通过，快照数量专项有改善；完整报告语义仍未通过。** 本轮没有重新制造故障，只对 [LOCK-02](basic-row-lock-boundary-v07.md) 已保存的历史证据做了一次受控重分析。公网故障开关继续关闭。

机器记录见 [basic-row-lock-sample-scope-v44.json](basic-row-lock-sample-scope-v44.json)。实际输入、输出及费用审计保存在私有运行目录，不把原始数据库数据和凭据发布到仓库。

## 缺口与修正

旧恢复报告的冻结清单有两份非空锁等待快照，模型最终却只收到了较晚的一份。它把“当前收到一份”说成“整个窗口只发生一次”，超出了输入范围。

离线逐步重放定位到：较早的一份在最初组装输入时就被漏掉，而非最后发给模型时才丢失。修正后保护同一来源、主机和监控项最早与最新的非空快照，保留来源身份；提示明确区分保留样本、完整窗口与故障次数。对受保护证据仍装不下的请求，按原预算拒绝，不能通过静默删除证据来生成结论。

## 先确认前提，再调用一次

本轮选择原恢复报告的相同历史窗口：**2026-11-12 17:05:48.023663—18:05:48.023663 UTC**（北京时间加 8 小时）。只读预演确认：

- 当前仍只选择锁等待快照和锁等待数量两项，选择版本未改变。
- 原窗口的 579 条原始引用与旧冻结清单完全相同，没有混入已移出的线程项或聚合指标帧。
- 数值窗口只有对应锁等待数量的 720 个点；不能把它与结构化快照的数量混为一谈。
- 当前权限、外发许可及预算可用。没有提高调用上限、重置日计数或修改巡检策略。

使用标准调查接口提交一次任务，通用问题只将开头改为“历史证据复核”，没有加入预期答案。关闭本次工具调用，使模型只作一次最终回答；这次手工任务不计作新的自主发现，也不伪称已计入自动巡检的日派发次数。

## 没有通过的部分

1. 报告写“已自行恢复”“约 2 分钟内自行解决”。后续空快照只能证明那些采样时刻未观察到等待，不能说明恢复方式，更不能据此确认持续时间。此次原演练实际由控制器关闭，但这个答案没有送给模型。
2. 一个事实句同时说“720 个数值样本”和“只保留 5 个非空/空样本”，却只引用数值窗口。720 属于数值序列，5 属于保留的锁快照；这两种数量的归属和引用仍不够清楚。
3. 某个时间范围句只引了后续空快照，没有同时列出它依赖的最后一份非空锚点，引用追溯仍有局限。

因此，本轮确认了**输入保留、身份隔离和预算边界有效，实际回答的快照数量表述改善**，但不宣称完整诊断、恢复方式或持续时间判断已通过。保留实际失败措辞和原始审计，不手工修改报告，也不为获得成功结果重复调用。后续应继续检查通用推理与输出约束，而不是加入这个场景的答案。
